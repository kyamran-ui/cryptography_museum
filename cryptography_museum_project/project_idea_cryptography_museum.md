# Маршрут цифрового дня — интерактивная игра выставки «Ключ к доверию»

Посетитель выставки «Ключ к доверию» (сайт Музея криптографии) за 5–7 минут проходит десять бытовых ситуаций цифровой безопасности: смартфон, такси, кафе, работа, банк, почта, вечер дома. Каждая ситуация — один вопрос с четырьмя вариантами ответа и баллом. После ответа сразу идёт разбор: карточки хакера и эксперта. Когда пройдены все десять тестов, посетитель получает индекс цифровой безопасности 0–100, именованный профиль, сильные стороны, зоны риска и памятку. Регистрации нет, персональные данные не собираются.

Это рабочая продуктовая спецификация для frontend: React-приложение в Docker передаётся Бастиону (музей). Backend принадлежит Бастиону; до появления API статистика и сохранение прохождений — моки. Вёрстку (особенно desktop) ревьюит и правит Кямран.

---

## 1. Проблема

Обучение цифровой гигиене на выставке не работает в привычных форматах: лекция на 40–90 минут не укладывается в стенд; плакаты и буклеты пролистывают за 15 секунд; корпоративные LMS требуют учёток и неприменимы на публичной площадке. Тест «что такое фишинг?» измеряет термины, а не решение за 2–3 секунды.

Посетитель субъективно «осторожен», но отдаёт такси-приложению контакты и фото или называет код из СМС «от банка». У него есть 5–7 минут, не час. Заказчику после стенда с плакатами нет данных, что аудитория реально не умеет. Регистрация на публичном мероприятии отсекает почти всех и создаёт обязанности оператора ПДн.

Интерактив на 5–7 минут даёт удержание и обезличенную статистику по темам. Для одного человека цена ошибки — прямые потери и часы на блокировку карт и восстановление доступов; для просветительской площадки — измеримый результат вместо «раздали буклеты».

---

## 2. Целевая аудитория

**Ядро.** Посетители выставки «Ключ к доверию», 14–45 лет, без подготовки по ИБ: есть карта, почта, приложения на телефоне. Играют у стенда со своего смартфона по QR или с устройства на стенде; после мероприятия — по ссылке в каналах заказчика.

**Вторичная.** Организаторы смотрят обезличенную статистику (когда её отдаст Бастион). Преподаватели и ИБ/HR могут взять ссылку как короткую вводную. Пользователи 55+ — через посредника, после сдачи: проще язык и крупный шрифт.

**Не для них.** Действующие ИБ-специалисты (наберут 92–100 и не узнают нового). Компании, которым нужна аттестация и персонифицированные протоколы (продукт анонимен). Курс на 10+ часов. Дети до 12 лет (банк, рабочая почта, такси).

Регистрации нет, монетизации для посетителя нет: разработку финансирует заказчик.

## 3. Продукт и ценность

Человек выбирает сценарии из меню десяти тестов, в каждом принимает одно решение, сразу видит разбор и набирает 0 / 3 / 5 / 10 баллов. Пока не сыграны все десять, именованный профиль скрыт; баллы по уже пройденным этапам видны только если открыть результаты. После полного маршрута — индекс 0–100, профиль, разбор по шести категориям, сильные стороны, зоны риска, памятка (PDF).

### Что делает frontend (MVP)

| # | Функция | Посетитель | Клиент |
|---|---------|------------|--------|
| 1 | Старт без регистрации | QR / «Пройти квест» | Анонимное прохождение, меню из 10 тестов |
| 2 | Один вопрос — один балл | Выбирает 1 из 4 ответов, жмёт «Ответить» (пропуск запрещён) | Фиксирует ответ, показывает разбор: очки + хакер + эксперт (тексты зависят от ответа и баллов), затем «Далее» |
| 3 | Прогресс маршрута | Видит `n/10` и чипы мест на экране вопроса | Счётчик — порядок игры, не «десять вопросов внутри одного пункта» |
| 4 | Индекс и профиль | Открывает результаты | До завершения всех 10: без имени профиля; после всех 10: индекс 0–100 и один из четырёх профилей |
| 5 | Разбор, памятка, повтор | Смотрит сильные стороны и риски, забирает чек-лист, «Пройти игру ещё раз» | Шесть категорий, PDF (индекс, профиль, сильные стороны, зоны риска, памятка). Повтор ведёт в **меню сценариев** |
| 6 | Статистика (клиент) | — | Запросы к API статистики — **моки**, пока нет бэкенда Бастиона |

### Что не входит в эту поставку frontend

- Регистрация, кабинеты, история конкретного человека, сертификаты, LMS/SCORM.
- Нативные iOS/Android, мультиязычность (только русский), рейтинги и командный режим.
- ИИ и адаптивный подбор сценариев, ветвление маршрута (выбор меняет баллы и тексты разбора, не следующий сюжет).
- Визуальный редактор сценариев в интерфейсе.
- Реализация backend, БД, агрегации статистики, админ-страницы статистики и деплой сервера музея — зона Бастиона. Клиент отдаёт Docker с React и контракт моков.

## 4. Игровой поток

1. **Главная.** Бейдж выставки «Ключ к доверию», заголовок «Маршрут цифрового дня», CTA в духе «пройти квест», мета ~7 мин и цифровой профиль в конце. Шапка: знак музея + **Бастион**.
2. **Меню выбора сценариев (обязательно).** Десять независимых тестов. Один пункт меню = одна ситуация = один вопрос = один балл. Экрана в Figma пока нет — не верстать вслепую (см. оставшиеся задания).
3. **Экран вопроса.** Чипы маршрута **только здесь** (отдельной карты дня нет). Счётчик `n/10` по порядку прохождения. Бейдж категории, иллюстрация, заголовок, четыре ответа, кнопка «Ответить» неактивна, пока нет выбора.
4. **Разбор сразу после ответа.** Иллюстрация скрывается. Карточка баллов (язык UI kit: опасное / небезопасное / безопасное; шкала очков **0 / 3 / 5 / 10**, визуал +3 — тот же kit). **Всегда** обе карточки: хакер (01) и эксперт (02, «Как правильно»). Тексты зависят от выбранного ответа и начисленных баллов. «Далее».
5. **Следующий сценарий** — снова через меню или по выбранному порядку игры; `n/10` растёт по факту пройденных.
6. **Результаты** — можно открыть и до конца десятки, но **именованный профиль скрыт**, пока не сыграны все 10. Баллы завершённых этапов на результатах — только если посетитель сам открыл этот экран. После всех 10: кольцо индекса, профиль, сильные стороны, зоны риска, статистика по шести категориям, скачивание чек-листа, шаринг, повтор.
7. **Повтор** → меню сценариев, не сразу в вопрос 1.

Чипы мест (подписи продукта; в макете Figma подписи ошибочны, ориентироваться на этот список):

| № | Место |
|---|--------|
| 1 | Смартфон |
| 2 | Такси |
| 3 | Кафе |
| 4–6 | Работа |
| 7 | Банк |
| 8 | Почта |
| 9–10 | Дом |

## 5. Баллы и профили

Каждый сценарий: четыре ответа, баллы **0 / 3 / 5 / 10**. Десять сценариев × 10 = **100** при полном прохождении. Индекс = сумма баллов по сыгранным тестам; полный индекс 0–100 — после всех десяти.

Именованный профиль показывается **только после всех 10**:

| Сумма | Профиль |
|------:|---------|
| 0–39 | Лёгкая цель |
| 40–59 | Доверчивый прохожий |
| 60–91 | Осторожный аналитик |
| 92–100 | Цифровой ниндзя |

В макете результатов сейчас заголовок «Осознанный пользователь» — это устаревший пример Figma, в продукт не брать.

**Полоски статистики — шесть категорий документа сценариев, не восемь баров Figma:**

| Категория | Сценарии |
|-----------|----------|
| Фишинг | 1, 7, 8 |
| Приватность | 2, 9 |
| Wi-Fi / Сети | 3 |
| Пароли / Аккаунты | 4, 5 |
| Устройства | 6, 10 |
| Финансы | 1, 7 |

Восемь подписей из макета (Смартфон, Пароли, Wi-Fi, Устройства, Офис, Банк, Интернет, Фишинг) — смешанная таксономия мест и тем, для продукта не использовать. Дополнительный тег сценариев «Социальная инженерия» — перекрывающий ярлык в контенте, не седьмая полоска.

PDF-памятка: индекс, профиль, сильные стороны, зоны риска, чек-лист. Шапка приложения везде с **Бастионом**.

## 9. Стек и передача Бастиону

**Стек (зафиксирован).** React + TypeScript + Vite, SPA. Сценарии в JSON в бандле, прогресс сессии в `localStorage`. Стили: токены Figma / CSS modules (Tailwind только на сетку, без shadcn). Роутер: React Router. **Не Next.js** — SSR Бастиону не нужен. Сборка: статика за **nginx** в **Docker**. API: адаптер; пока `VITE_API_BASE_URL` пустой — мок `POST /runs` из fixtures; Бастион подставит URL при сборке образа. ТЗ музея: стек по желанию команды, пример совпадает с этим.

**Моки до бэкенда.** Статистика и любые вызовы API — локальные/мок-ответы с тем же контрактом, который потом подключит Бастион. Не проектировать и не описывать здесь чужую БД, админку и OpenAPI как нашу реализацию.

**Контент.** Сценарии, варианты, баллы, категории, тексты хакера и эксперта — данные, отдельно от экранов. Добавление сцены не должно требовать переписывания UI.

**Ограничения площадки.** Адаптив смартфон и ПК, основные браузеры, открытие по QR, стенд с одновременными посетителями. Без сторонней веб-аналитики в клиенте: учёт — через Бастион. Юрисдикция Россия. ПДн не запрашивать ни на одном экране. Русский язык.

**Документация в поставке клиента.** README, как собрать и запустить Docker, как подменить моки на боевой API Бастиона, когда он появится. Архитектура сервера, требования к VPS и админка статистики — не зона этой спецификации.

## 10. Критерии успеха (продукт у стенда)

- Посетитель проходит игру без регистрации и без полей ФИО/email/телефона.
- Десять сцен, обязательный ответ, разбор хакер+эксперт после каждого выбора, индекс после полного маршрута, четыре профиля, шесть категорий, памятка, повтор в меню.
- Формат удерживает 5–7 минут: доля дошедших до полного набора тестов ориентир ≥ 70 %; медиана 4–8 минут; средний индекс первого полного прохождения ориентир 45–75 (слишком легко/сложно — править контент).
- Ноль критичных сбоев старта и завершения на стенде (телефон и ПК).
- Бастион может развернуть отданный Docker и позже подставить свой API вместо моков.

Метрики активации, повторных прохождений и «провальных» категорий имеет смысл считать, когда заработает статистика Бастиона.
