| Поле | Значение |
|------|----------|
| Версия | 1.2 |
| Статус | Production-ready |
| Дата | 2026-09-13 |
| Аудитория | автономные агенты Cursor (frontend-поставка музею) |

Документ описывает **клиентское SPA**, которое команда отдаёт **Бастиону** (Docker + статика). Backend, БД, админка статистики и деплой сервера музея **не реализуются** в этом репозитории.

---

## 0. Overview

### 0.1 Продукт

Интерактивная игра выставки «Ключ к доверию» (Музей криптографии). Посетитель за **5–7 минут** проходит **десять независимых тестов** цифровой безопасности. Каждый тест — **одна ситуация, четыре ответа, один балл** `0 | 3 | 5 | 10`. Сразу после ответа — разбор: карточка хакера и карточка эксперта. После всех десяти — индекс **0–100**, именованный профиль, сильные стороны, зоны риска, шесть категорий, PDF-памятка.

**Регистрации нет. ПДн не собираются. Полей ФИО / email / телефон / аккаунт нет ни на одном экране.**

### 0.2 Роли

| Роль | В нашем приложении |
|------|-------------------|
| Посетитель (аноним) | Единственный пользователь UI. Играет со смартфона по QR или с планшета стенда. |
| Оператор стенда | Не имеет отдельного UI. Перезапускает игру кнопкой «Пройти игру ещё раз» между посетителями. |
| Бастион (handoff frontend) | Принимает Docker-образ, подставляет `VITE_API_BASE_URL`, проксирует `POST /runs`. Админка статистики — их зона. |

Админ-UI в этом приложении **нет**.

### 0.3 Зафиксированный стек (нарушать запрещено)

| Слой | Решение |
|------|---------|
| UI | **React 19** + **TypeScript** |
| Сборка | **Vite** (SPA, `index.html` + `src/`). Не App Router, не `app/`, не `next.config`. |
| Роутинг | **React Router** v7 (createBrowserRouter / BrowserRouter) |
| Стили | CSS custom properties из Figma + **CSS modules** на компоненты UI kit. **Tailwind только** на layout-сетку (`grid`/`flex`/`gap`/`max-w`). **shadcn/ui запрещён.** |
| Иконки | Ассеты Figma / музея (места, стрелки, header). **Lucide** — только если нужной иконки нет в kit (шаринг copy / check). |
| Контент | JSON в бандле: `src/content/scenarios.json` |
| Сессия | `localStorage`, анонимный id |
| Доставка | Multi-stage Docker: `node` собирает Vite → **nginx:alpine** отдаёт `dist`, SPA fallback на `index.html` |
| API | Адаптер `src/api/*`. Если `VITE_API_BASE_URL` пустой — мок. Если задан — реальный `POST`. |
| Шрифты | Halvar webfonts из store `media/fonts/`. Bahnschrift и BBH Bogle — CSS-имена + системные фолбэки (файлов заказчик не отдал). |

**Запрещено в этой поставке:** Next.js, Supabase, Auth, платежи, Telegram, Anthropic/OpenAI, Vercel, YooKassa, Prisma, Postgres как наша реализация, сторонние веб-аналитики, i18n-фреймворк, нативные приложения.

### 0.4 Маршруты SPA

| Путь | Экран |
|------|--------|
| `/` | Главная |
| `/menu` | Меню десяти сценариев |
| `/play/:scenarioId` | Вопрос или разбор (состояние из сессии) |
| `/results` | Результаты (частичные или полные) |

Прямой заход на `/play/s01` без сессии создаёт сессию и открывает вопрос, если сценарий не пройден.

### 0.5 Критерии приёмки MVP

- Старт без регистрации, 10 сцен, обязательный ответ, хакер+эксперт после каждого выбора.
- Индекс и **имя профиля** только после всех 10. До этого — скрытый профиль, баллы только на экране результатов, если посетитель сам его открыл.
- Повтор → `/menu`, не в первый вопрос.
- `docker compose up` поднимает статику. Пустой `VITE_API_BASE_URL` = мок `POST /runs`.
- Юрисдикция РФ, только русский, QR и стенд, мобильный 360 + широкая desktop-сетка.

### 0.6 Внешние ссылки (канон)

- Figma файл `uBGQGyWe3uSTMMy52r2poX`: готовые экраны `2541:1961`, UI kit `2541:3484`, Spectral `2541:3931`, результаты `2541:4499`, статистика `2541:4667`.
- Сайт музея (CTA «На сайт музея»): `https://cryptography-museum.ru/` — в документе сценариев URL не было; зафиксирован официальный сайт музея.
- Документ сценариев — канон сюжетов и баллов; Figma Q1 «Утренний возврат» — канон **состояний** экрана вопроса/разбора, не сюжета.

## 1. User Stories

Роли в историях: **посетитель**, **оператор стенда**, **инженер Бастиона (handoff)**. Не «пользователь».

### US-01. Посетитель начинает квест с QR без учётки

**Как** посетитель выставки 14–45 лет со смартфоном, **я хочу** открыть ссылку по QR и сразу увидеть главную с CTA «пройти квест», **чтобы** за 5–7 минут сыграть, не оставляя телефон и имя.

Happy path: QR → `/` → шапка музей+Бастион, бейдж «Выставка “ключ к доверию”», H1 «Маршрут цифрового дня», мета «~7 мин», «цифровой профиль в конце» → кнопка → `/menu`. В `localStorage` появляется сессия с `anonymousId` (UUIDv4) и пустым `answers`.

Error path: JSON контента не распарсился. Главная показывает блок ошибки «Не удалось загрузить игру» + «Обновить страницу». Полей ввода нет.

### US-02. Посетитель выбирает любой непройденный тест из меню

**Как** посетитель у стенда, **я хочу** видеть десять карточек мест и сам выбирать порядок, **чтобы** успеть интересующие ситуации, если очередь сзади.

Happy path: `/menu` → 10 карточек (иконка места, номер, заголовок). Непройденные доступны. Тап → `/play/s0N` в режиме вопроса.

Error path: тап по уже пройденному открывает **только разбор** (ответ зафиксирован). Primary разбора: «Следующий вопрос» к следующему непройденному в порядке чипов либо «Смотреть результат», если десятка закрыта — **не** в `/menu`. Попытка подменить `scenarioId` в URL на неизвестный (`/play/s99`) → редирект `/menu` + тост «Такого теста нет».

### US-03. Посетитель отвечает и сразу видит хакера и эксперта

**Как** посетитель, **я хочу** выбрать один из четырёх ответов, нажать «Ответить» и увидеть очки плюс две карточки, **чтобы** понять ошибку за 20 секунд, а не после всего теста.

Happy path: выбор подсвечивает `answer_button` синим `#1E53E6`. «Ответить» становится primary. POST в API на этом шаге **нет**. Показывается карточка баллов (0/3/5/10) + hacker `01` + expert `02`. Тексты берутся из выбранного варианта. С разбора **не** возвращаемся в `/menu`. Primary **«Следующий вопрос»** → `/play/:id` следующего непройденного в каноническом порядке чипов (§2.4 / §5.5). Если непройденных не осталось — **«Смотреть результат»** → `/results`.

Error path: двойной тап «Ответить» не перезаписывает балл (идемпотентная запись). «Ответить» без выбора остаётся disabled (ghost 50%).

### US-04. Посетитель смотрит частичные результаты без имени профиля

**Как** посетитель после 3–4 тестов, **я хочу** открыть результаты и увидеть сумму уже сыгранного, **чтобы** понять прогресс, не получая «звание», пока день не закончен.

Happy path: из шапки/меню ссылка «Результаты» → `/results`. Кольцо показывает текущую сумму (например 18 при трёх ответах). Блок профиля скрыт целиком. Полоски шести категорий считаются только по пройденным сценам этой категории. CTA «Вернуться к меню».

Error path: `/results` при нуле ответов — empty: «Вы ещё не прошли ни одного теста» + кнопка в меню. Имя профиля, PDF с профилем и шаринг индекса **не показываются**.

### US-05. Посетитель завершает десятку, забирает памятку и делится счётом

**Как** посетитель после 10/10, **я хочу** увидеть индекс, один из четырёх профилей, сильные стороны, риски, чек-лист и поделиться текстом, **чтобы** унести практический вывод с выставки.

Happy path: кольцо 0–100, профиль, **две** сильные стороны и **две** зоны риска (§5.4: два наибольших и два наименьших percent, без порога 80/50), аккордеон «Статистика» с **шестью** категориями, «Скачайте чек-лист безопасности» (клиентский PDF), шаринг (Web Share API или копирование), «Пройти игру ещё раз» → новая `runId`, пустые `answers`, `/menu`. Один вызов `POST /runs` после фиксации 10-го ответа.

Error path: PDF не собрался — тост «Не удалось сформировать файл, попробуйте ещё раз», игра не сбрасывается. `POST /runs` упал — сессия на устройстве сохранена, повторная отправка при следующем заходе на `/results` (флаг `synced`).

### US-06. Оператор стенда запускает игру для следующего человека

**Как** оператор стенда на планшете музея, **я хочу** одной кнопкой «Пройти игру ещё раз» очистить ответы, **чтобы** следующий посетитель не видел чужой индекс 85 и профиль «Цифровой ниндзя».

Happy path: повтор сбрасывает `answers`, `completedAt`, `synced`, генерирует новый `runId`. `anonymousId` устройства **сохраняется** (это не ПДн, это id браузера стенда). Экран — меню, не вопрос 1.

Error path: `localStorage` QuotaExceeded — сессия в memory, баннер «Прогресс может не сохраниться при обновлении. Обновите вкладку или сообщите оператору».

### US-07. Инженер Бастиона подменяет мок на боевой API

**Как** инженер Бастиона на handoff frontend, **я хочу** собрать образ с `VITE_API_BASE_URL=https://api.museum.example/v1` без правок экранов, **чтобы** обезличенные прохождения попали в их статистику.

Happy path: тот же контракт `POST /runs`. Клиент не ходит в другие path.

Error path: 4xx/5xx с телом `{ "error": { "code", "message" } }` — клиент логирует в console в DEV, посетителю не показывает сырой JSON; флаг `synced=false`. CORS с моком не проверяется (N/A). Ожидания к Бастиону — блок 5.

## 2. Data Model

Хранилище клиента: **JSON в бандле + localStorage**. Postgres в нашем коде нет.

### 2.1 Идентификаторы

| Сущность | Формат | Пример |
|----------|--------|--------|
| scenarioId | `s` + две цифры | `s01` … `s10` |
| answerId | `A` \| `B` \| `C` \| `D` | `D` |
| placeId | kebab | `smartphone` |
| categoryId | kebab | `phishing` |
| anonymousId, runId | UUID v4 | `3d1c0a7e-6b21-4f0c-9a11-2c8f0e4d7b91` |
| score | `0 \| 3 \| 5 \| 10` | `10` |
| profileId | enum | `easy_target` |

### 2.3 Zod-схемы (копировать в `src/content/schema.ts` и `src/session/schema.ts`)

```ts
import { z } from "zod";

export const ScoreSchema = z.union([
  z.literal(0),
  z.literal(3),
  z.literal(5),
  z.literal(10),
]);

export const AnswerIdSchema = z.enum(["A", "B", "C", "D"]);

export const PlaceIdSchema = z.enum([
  "smartphone",
  "taxi",
  "cafe",
  "work",
  "bank",
  "mail",
  "home",
]);

export const CategoryIdSchema = z.enum([
  "phishing",
  "privacy",
  "wifi",
  "accounts",
  "devices",
  "finance",
]);

export const AnswerSchema = z.object({
  id: AnswerIdSchema,
  text: z.string().min(8).max(240),
  score: ScoreSchema,
  hacker: z.string().min(12).max(600),
  expert: z.string().min(24).max(900),
});

export const ScenarioSchema = z.object({
  id: z.string().regex(/^s(0[1-9]|10)$/),
  order: z.number().int().min(1).max(10),
  placeId: PlaceIdSchema,
  chipLabel: z.enum([
    "Смартфон",
    "Такси",
    "Кафе",
    "Работа",
    "Банк",
    "Почта",
    "Дом",
  ]),
  categoryIds: z.array(CategoryIdSchema).min(1).max(3),
  overlayTag: z.literal("social_engineering").optional(),
  theme: z.string(),
  badge: z.string().max(32),
  title: z.string().min(4).max(80),
  situation: z.string().min(40),
  illustration: z.string().regex(/^\/illustrations\/s\d{2}\.(webp|png|svg)$/),
  answers: z.tuple([AnswerSchema, AnswerSchema, AnswerSchema, AnswerSchema]),
});

export const ScenariosFileSchema = z.object({
  version: z.literal(1),
  exhibition: z.literal("Ключ к доверию"),
  productTitle: z.literal("Маршрут цифрового дня"),
  museumSiteUrl: z.string().url(),
  scenarios: z.array(ScenarioSchema).length(10),
});

export const StoredAnswerSchema = z.object({
  scenarioId: z.string().regex(/^s(0[1-9]|10)$/),
  answerId: AnswerIdSchema,
  score: ScoreSchema,
  answeredAt: z.string().datetime(),
});

export const SessionStateSchema = z.object({
  version: z.literal(1),
  anonymousId: z.string().uuid(),
  runId: z.string().uuid(),
  startedAt: z.string().datetime(),
  completedAt: z.string().datetime().nullable(),
  synced: z.boolean(),
  answers: z.array(StoredAnswerSchema).max(10),
});
```

                    │  anonymousId, runId, answers[]  │
                    │  completedAt, synced            │
                    └───────┬─────────────┬───────────┘

|-----:|------|--------|

### 3.3 Zod HTTP

```ts
import { z } from "zod";
import { AnswerIdSchema, CategoryIdSchema, ScoreSchema } from "../content/schema";

export const PostRunAnswerSchema = z.object({
  scenarioId: z.string().regex(/^s(0[1-9]|10)$/),
  answerId: AnswerIdSchema,
  score: ScoreSchema,
});

export const PostRunCategorySchema = z.object({
  id: CategoryIdSchema,
  earned: z.number().int().min(0),
  max: z.number().int().positive(),
  percent: z.number().int().min(0).max(100),
});

export const PostRunRequestSchema = z.object({
  anonymousId: z.string().uuid(),
  runId: z.string().uuid(),
  startedAt: z.string().datetime(),
  completedAt: z.string().datetime(),
  index: z.number().int().min(0).max(100),
  profileId: z.enum([
    "easy_target",
    "trusting_passerby",
    "careful_analyst",
    "digital_ninja",
  ]),
  answers: z.array(PostRunAnswerSchema).length(10),
  categories: z.array(PostRunCategorySchema).length(6),
  contentVersion: z.literal(1),
  client: z.literal("mdd-web"),
});

export const PostRunResponseSchema = z.object({
  ok: z.literal(true),
  runId: z.string().uuid(),
  stored: z.boolean(),
});

export const ApiErrorSchema = z.object({
  error: z.object({
    code: z.string().min(1),
    message: z.string().min(1),
  }),
});
```

### 3.4 Мок

`src/api/mock.ts`: кладёт прохождение в массив (max 50), отвечает `{ ok: true, runId, stored: true }`. CORS и rate limit **N/A**. Не эмулировать 429 в happy-path; для DEV можно `?mockError=1` не делать — агенты не тратят время на скрытые флаги. Ошибку сети мок не бросает.

### 5.1 Аутентификации нет

Ни OAuth, ни cookie сессии сервера, ни JWT. Шаги анонимной сессии:

1. Первый заход: `crypto.randomUUID()` → `anonymousId` и `runId`, `startedAt=now()`, `answers=[]`, `synced=false`, `completedAt=null`, запись в `mdd.session.v1`.
2. Каждый ответ: append в `answers`, unique по `scenarioId`. Повторная запись того же id игнорируется.
3. После 10-го ответа: `completedAt=now()`, расчёт профиля, `postRun`, при успехе `synced=true`.
4. «Пройти игру ещё раз»: сохранить `anonymousId`, новый `runId`, очистить answers/completed/synced, `startedAt=now()`.
5. Закрытие вкладки не логинит никого. Другой браузер = другой `anonymousId`.

### 5.2 Ответ и баллы

Нельзя пропустить. Один ответ на сценарий. Баллы строго `0/3/5/10` из JSON, клиент **не** пересчитывает смысл ответа. Индекс = сумма `score`. Полный максимум 100.

Частичные очки на главной и в меню **не** показывать. На вопросе после ответа — карточка этого шага. Сумма и категории — на `/results`.

### 5.3 Профиль

Функция `profileFromIndex(index: number): ProfileId` вызывается **только** если `answers.length === 10`. Иначе `profileId = null`.

```
0–39 easy_target
40–59 trusting_passerby
60–91 careful_analyst
92–100 digital_ninja
```

Границы включительно как в таблице. 39 → Лёгкая цель, 40 → Доверчивый прохожий, 91 → Осторожный аналитик, 92 → Цифровой ниндзя.

Тела профилей (Figma-дубль плейсхолдера не использовать):

| id | body |
|----|------|
| easy_target | Вы часто соглашаетесь на удобный вариант. Мошеннику достаточно одного звонка, письма или «обновления». Пройдите памятку и начните с кодов из СМС и ссылок. |
| trusting_passerby | Часть угроз вы чувствуете, но дожимаете диалог или отдаёте «чуть-чуть» данных. Держите правило: секреты и разрешения — только по официальному каналу. |
| careful_analyst | Вы уже останавливаетесь на проверке адреса, разрешений и 2FA. Зоны роста — привычки, где экономите секунду. |
| digital_ninja | Вы закрываете типичные атаки дня. Держите планку: уникальные пароли, официальные магазины, недоверие к входящим «банкам». |

### 5.4 Категории, сильные, риски

`earned` = сумма баллов сцен категории, которые **отвечены**. `max` — полный максимум категории (§2.4), даже если сценарий не играли. `percent = round(earned / max * 100)`. Полоски — все **шесть** категорий; процент считается по ответам посетителя к max этой категории.

Канонический порядок категорий (tie-break и «все равны»): **Фишинг, Приватность, Wi-Fi / Сети, Пароли / Аккаунты, Устройства, Финансы** (§2.4).

После **всех 10** карточки (порогов **≥80% / <50% нет** — абсолютный процент не решает, показывать карточку или нет):

1. В отбор входят категории, у которых есть хотя бы один отвеченный сценарий (после 10/10 — все шесть).
2. **Сильные стороны:** всегда **две** категории с наибольшим `percent`.
3. **Зоны риска:** всегда **две** с наименьшим `percent`.
4. Tie-break: выше percent побеждает для сильных (для рисков — ниже percent). При равном percent — кто **раньше** в каноническом списке.
5. Тема **не дублируется** на обоих списках. Если категория попала бы и в сильные, и в риски (одна–две категории с данными, все percent равны): **предпочтение силе, не риску**.
6. Если все шесть percent равны: две сильные — **первые две** канонического порядка (Фишинг, Приватность); две риски — **последние две** (Устройства, Финансы).
7. Если категорий с данными **1**: одна сильная, рисков нет. Если **2**: обе сильные, рисков нет. Если **3–5**: две сильные, затем две риски из **оставшихся** (наименьший percent, тот же tie-break).

Empty только если список после шагов выше пуст: сильные — «Пока нет устойчивых тем — это нормально, откройте памятку.»; риски — «Критических провалов по темам нет. Держите привычки.» После полного маршрута из десяти сцен empty недостижим для сильных и почти недостижим для рисков (риски пусты лишь при 1–2 категориях с данными).

До 10/10 блоки сильных/рисков не рендерятся (иначе профиль «по смыслу» утекает).

### 5.5 Чипы, n/10 и переход с разбора

`n/10` = число **завершённых** тестов в разборе; на активном новом вопросе отображается `completed+1`. Старт и прыжок: посетитель может открыть s10 раньше s02 **через `/menu`**. После разбора порядок фиксирован.

Канонический порядок чипов / `order` (не порядок фактических ответов в `answers[]`):

1 Смартфон (`s01`) → 2 Такси (`s02`) → 3 Кафе (`s03`) → 4–6 Работа (`s04`, `s05`, `s06`) → 7 Банк (`s07`) → 8 Почта (`s08`) → 9–10 Дом (`s09`, `s10`).

**Следующий непройденный** после разбора сцены `S`: первый сценарий с `order` строго больше `S.order`, которого нет в `answers`; если таких нет — первый непройденный с начала списка (кольцо). Если непройденных нет — CTA «Смотреть результат» → `/results`. Пример: старт из меню с `s07` → после разбора `s08` (если не отвечен), иначе дальше по списку, затем `s01`…`s06`, пропуская уже сыгранные.

CTA главной «пройти квест» по-прежнему → `/menu` (picker обязателен, чтобы начать или прыгнуть). «Пройти игру ещё раз» → `/menu`, не в `s01`.

### 5.6 Повтор и идемпотентность API

Новый `runId` на повтор. Повторный `POST` с тем же `runId` после refresh — ок. Не слать два разных тела с одним `runId`.

### 5.7 Rate limit и CORS

Мок: **N/A** (нет сети).

Ожидания к Бастиону (мы не кодируем): CORS `Access-Control-Allow-Origin` = origin статики игры (и `https://cryptography-museum.ru` если игра на поддомене); `POST`, `OPTIONS`; `Content-Type`. Лимит: не жёстче **60 POST /runs в минуту с одного IP** (стенд + класс). Тело ≤ 16 KB. Не требовать cookie. Не писать IP в публичные отчёты как идентификатор человека.

### 5.8 Контент отдельно от UI

Новая сцена = правка JSON + иллюстрация. Компоненты читают поля, не хардкодят тексты s01–s10 кроме fallback error strings.

### 5.9 Доступность и стенд

Язык `html lang=ru`. Тап-цели ≥ 44px. Фокус видимый на кнопках. Не автоиграть звук. Одновременные посетители = разные устройства = разные LS. Планшет стенда: оператор делает replay между людьми.

### 5.10 Аналитика клиента

Сторонняя (Яндекс.Метрика, GA) **запрещена**. Учёт — `POST /runs` у Бастиона.

## 6. Edge Cases

1. **Двойной клик «Ответить».** Вторая обработка no-op, score не меняется.
2. **Назад браузера с разбора на вопрос.** Показать разбор, не форму. History: после ответа `replace` тот же URL.
3. **Reload на середине вопроса (выбор не отправлен).** Выбор в React state сбрасывается, кнопка снова disabled. Не писать draft в LS (черновик провоцирует «случайный» ответ).
4. **Reload после ответа, до CTA разбора («Следующий вопрос» / «Смотреть результат»).** Снова разбор.
5. **Прямой URL `/play/s07` при непройденных других.** Разрешено, создаётся/продолжается run.
6. **Прямой `/results` в новой вкладке того же браузера.** Читает LS; если пусто — empty.
7. **Две вкладки.** `storage` event: вторая вкладка подтягивает answers. Конфликт двух одновременных «Ответить» на разные сцены — обе пишут, last-write-wins по полной сессии; запретить две разные записи одной сцены.
8. **localStorage недоступен (Safari private / запрет).** In-memory store + баннер. Replay работает до закрытия вкладки.
9. **QuotaExceededError.** Как п.8.
10. **Битый JSON в LS.** Backup + новая сессия, не падать белым экраном.
11. **Неполный answers (удалили вручную одну запись).** Считать по фактическому массиву; `completedAt` сбросить если length<10; `synced=false`.
12. **Подделка score в LS (s01 score 10 при answer A).** При чтении пересчитать score из бандла JSON. Клиентский чит на стенде не интересен; в POST уходит пересчитанный балл.
13. **Неизвестный scenarioId в LS.** Запись выкинуть.
14. **Шрифты Halvar не загрузились.** Fallback Arial Narrow / sans-serif, вёрстка не прыгает за счёт `size-adjust` по возможности; игра играбельна.
15. **Web Share отсутствует (desktop Chrome без support).** Кнопка share скрыть, оставить copy.
16. **Clipboard запрещён.** Тост «Скопируйте текст вручную» + `<pre>` с текстом шаринга, без prompt().
17. **PDF в старом WebView стенда падает.** Тост, оставить экран результатов.
18. **Офлайн после загрузки бандла.** Игра полностью офлайн. POST ставит `synced=false`, retry при `online` событии если complete.
19. **`VITE_API_BASE_URL` с хвостовым `/`.** Срезать в `env.ts`, не получить `//runs`.
20. **Ответ 200 HTML (включили SPA fallback на /runs).** `apiFetch` проверяет `content-type` JSON, иначе ошибка INTERNAL локально, не `JSON.parse` exception наружу.
21. **10/10 все нули.** Профиль «Лёгкая цель», индекс 0, кольцо 0, PDF валиден. Все категории 0% — как при равенстве: сильные Фишинг и Приватность, риски Устройства и Финансы.
22. **10/10 все десятки.** «Цифровой ниндзя», 100, все категории 100%. Сильные: Фишинг и Приватность; риски: Устройства и Финансы (все percent равны → первые две / последние две канона). Empty рисков **нет**.
23. **Ровно 40 и ровно 92.** Нижняя граница соответствующего профиля.
24. **Категория из одной сцены (wifi) на 5 баллов.** Полоска 50%. Карточки **не** зависят от порога 50/80: wifi попадает в сильные или риски только если её percent среди двух наибольших или двух наименьших (и не занята силой при конфликте).
25. **Оператор не нажал replay, новый посетитель видит чужие результаты.** Не лечится биометрией. На `/` если `isComplete` — вместо CTA «пройти квест» показывать primary «Пройти игру ещё раз» **и** ghost «К результатам». Решение для стенда: оператору проще попасть в replay с главной.
26. **QR открыл `/results` с чужого экрана в истории.** History не содержит score. Deep link только пути §0.4.
27. **Иллюстрация 404.** Пустой контейнер, alt «ситуация {title}», вопрос живой.
28. **Очень длинный хакер-текст.** Карточка скроллится внутри экрана, primary CTA разбора (`«Следующий вопрос»` / `«Смотреть результат»`) `position: sticky` низ.
29. **Ориентация landscape телефон.** Чипы горизонтальный scroll, не сжатие подписей до обрезки «Смарт…».
30. **Сравнение с Figma Q1 «Утренний возврат».** Вёрстка состояний как в кадре, **тексты и баллы** из JSON s01 «Звонок из банка».
31. **Повторный POST при `synced=true`.** Не вызывать сеть.
32. **Часовой пояс.** Все timestamps `toISOString()` UTC. На UI даты не показываем.

## Приложение A. Контракт для Бастиона, мы не реализуем

Короткий ориентир, не схема нашей БД и не RLS нашего проекта.

Бастион может хранить `runs(run_id PK, anonymous_id, started_at, completed_at, index, profile_id, answers jsonb, categories jsonb, content_version)`. Индекс по `completed_at`, `profile_id`. Публичного чтения таблицы из браузера нет. RLS/Postgres политики — на их стороне; клиент ходит только в `POST /runs`. Админка агрегатов (средний индекс, доля профилей, провальные категории) — не экраны этой поставки.
